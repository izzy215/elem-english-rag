## 1. 학습 완료 판정 (진행률의 기준)

| 상태 | 결정 | 근거 |
|---|---|---|
| 단어 "학습함" | 카드가 화면에 한 번 표시되면 학습함. 듣기·말하기는 조건 아님 | 초등 사용자에게 강제 조건은 이탈 요인. 듣기는 TTS 담당 구현 전엔 동작하지 않으므로 조건에 넣으면 진행률이 안 오름 |
| Unit 진행률 % | 학습한 단어 수 ÷ Unit 단어 수 (문장은 안 셈) | 문장 학습은 선택. 단어 기준이 단순하고 데모에서 설명하기 쉬움 |
| Unit "완료" | 문제를 1회 이상 풀고 **마지막 풀이에서 오답 0** | "다시 풀기"로 오답을 없애는 게 핵심 루프의 끝. 완료 배지는 Unit 카드에 ✓ |
| 복습 필요 표시 | 그 학생의 wrong_words 중 이 Unit 단어가 1개 이상 | Unit 카드에 "복습할 단어 n" (이미 구현) |

**미정**: 문장 카드도 진행률에 넣을지 (기본: 안 넣음). 8일차에 데이터 보고 결정.

## 2. 학생 전환

| 항목 | 결정 |
|---|---|
| 전환 위치 | 시작 화면(index.html)에서만. 다른 화면엔 학생 선택 없음 |
| 전환 시 상태 | Level·Unit·단어 목록·문제 결과 전부 초기화 (`S.set` 의 student 외 키 null) |
| 데모용 학생 | A = 오답 이력 있음(rabbit·jump 미리 심음), B = 이력 없음. 발표 7번 장면용 |
| 초기화 방법 | 관리자 화면에 "학생 데이터 초기화" 버튼 (△). 없으면 `data/student/` 파일 삭제로 대체 |

## 3. 화면별 상태 (로딩 · 정상 · 빈 · 오류)

문구 원칙: 존댓말 "~해요", 실패는 격려 톤, 기술 용어 없음. 서버·개발자용 안내는 회색 작은 글씨(`.hint`)로 분리.

| 화면 | 로딩 | 빈 데이터 | 오류 |
|---|---|---|---|
| 시작 | "불러오는 중…" | Level 카드 "준비 중" (클릭 불가) | 하단 상태줄에 서버 실행 명령 |
| Unit 목록 | 카드 자리 "불러오는 중…" | "이 Level에는 아직 Unit이 없어요" | 진행률만 0%로 두고 목록은 표시 |
| 학습 | 카드 "불러오는 중…" | "카드가 없어요" + 뒤로 | 듣기 실패 → 카드 아래 한 줄, 카드는 유지 |
| 문제 | "문제를 만드는 중… (최대 30초)" + 진행 점 | 단어 4개 미만 → "문제를 만들 단어가 부족해요" | 서버 실패 → 화면 임시 문제로 자동 전환, 상단에 "임시 문제" 표시 |
| 결과 | — | — | — |
| 오답 설명 | 카드마다 "설명을 준비하는 중…" | 틀린 문제 없음 → "틀린 문제가 없어요 🎉" | 설명 실패 → "준비 중" + 교재 예문·쪽수로 대체 |
| 관리자 | 각 패널 "확인 중…" | 정확도 "측정 전" | 등록 API 없음 → "API 필요" 안내 |

## 4. 예외 흐름

| 상황 | 화면 동작 | 결정 근거 |
|---|---|---|
| 서버 다운 | 모든 화면 하단 상태줄 빨간 글씨 + 실행 명령. 화면 자체는 그려짐 | 팀원이 서버 안 켜고 화면만 열어보는 경우가 가장 흔함 |
| API 키 없음 | 상태줄 "⚠ GEMINI_API_KEY 없음". 문제는 임시 문제, 설명·TTS는 준비 중 | 키 없이도 화면 전체를 둘러볼 수 있어야 데모 리허설이 됨 |
| Gemini 429/할당량 | 서버가 `detail`에 "잠시 후 다시" 포함 → 화면은 임시 문제/준비 중으로 폴백 + 상태줄 경고 | 발표 중 한도 소진 대비 |
| 마이크 거부 | "마이크를 사용할 수 없어요. 브라우저 권한을 확인하세요." 듣기·카드는 계속 | 말하기는 부가 기능 |
| 녹음 무음 | 서버 score 0 → "잘 안 들렸어요. 한 번 더 해볼까요?" (실패로 세지 않음) | 초등 사용자 좌절 방지 |
| 30초 대기 | 문제 화면에 안내 문구 + 진행 점 애니메이션. 45초 넘으면 임시 문제로 전환 | 무한 대기 방지 |
| 주소 직접 입력 | 필요한 상태 없으면 시작 화면으로 (`requireState`) | 이미 구현 |

**미정**: 45초 타임아웃 값. 실제 응답 시간 보고 8일차 조정.

## 5. UI 규칙 (초등 대상)

| 항목 | 결정 |
|---|---|
| 기준 폭 | 모바일 375px 우선, 최대 420px. 관리자만 760px |
| 글자 | 카드 단어 2.1rem, 본문 15px 이상, 힌트 12.8px |
| 터치 영역 | 버튼 높이 44px 이상 (현재 `.btn` 13px 패딩 → 약 46px) |
| 색 의미 | 초록 = 정답·완료·주요 동작 / 빨강 = 오답·경고 / 주황 = 준비 중·임시 / 회색 = 비활성 |
| 이모지 | 격려 문구에만 (🎉 👋). 버튼 아이콘은 🔊 🎙 두 개로 제한 |
| 애니메이션 | 없음. 카드 전환도 즉시 (모션 민감 사용자 고려, 구현 단순) |
| 뒤로 가기 | 브라우저 뒤로 + 상단바 "‹ 뒤로" 동일 동작 |

## 6. 화면 간 상태 키 (`js/common.js` · sessionStorage `echo`)

| 키 | 값 | 쓰는 화면 |
|---|---|---|
| student | "A" / "B" | 전부 |
| level | {level, label} | units 이후 |
| unit | {unit, title} | learn 이후 |
| words, sentences | 배열 (API 응답 그대로) | quiz(임시 문제), explain(예문 대체) |
| quizResult | {id, mock, questions, answers} | explain |

새 키를 추가하면 이 표에 적는다.
