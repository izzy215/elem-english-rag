# 설계 · 문제 생성 · 채점 · 오답 설명 (design-quiz) v0.1 초안

담당: 팀장 · 작성 2026-09-04 · 상위 문서: [PRD](PRD.md) 5.4 · 6.2 · 7절
파일: `backend/quiz.py` `backend/explain.py` `backend/student.py`(학생 DB, 신설 예정) `backend/prompts/`
형식: **결정**(기본값) / **근거** / **미정**.

---

## 1. 입력과 출력

```
입력  student · level · unit · count(기본 3, 최대 5)
      + Unit 단어 목록 (golden.words)
      + 이 학생의 wrong_words (우선순위 순)
      + RAG 조각 (rag.search, 단어별 1개)          ← rag.py 구현 전엔 없음 → 조각 없이 생성
출력  PRD 5.4 형식 그대로 (quiz_id, questions[])
```

## 2. 출제 구성 규칙 (오답 반영의 핵심)

| 규칙 | 결정 | 근거 |
|---|---|---|
| 오답 단어 수 | `ceil(count / 2)` 개까지. count=3 → 최대 2개 | "절반 이상"을 구체화. 전부 오답이면 새 단어를 못 배움 |
| 오답 단어 선택 | wrong_words 우선순위 순 (count 내림차순 → 최근순). **이 Unit 단어만** | 다른 Unit 오답은 그 Unit에서 |
| 나머지 단어 | Unit 단어 중 **아직 문제로 안 나온 것** 우선, 다 나왔으면 무작위 | 같은 3문제 반복 방지 |
| 반복 상한 | 같은 단어가 연속 3회 quiz에 나오면 1회 쉼 | 한 단어만 계속 틀리는 학생 배려 |
| 출제 순서 | 오답 단어를 **1번 문제**에 | 데모 7번 장면 "틀린 단어가 먼저 나온다"가 눈에 보이게 |
| 단어 부족 | Unit 단어 < 4 → 같은 Level 다른 Unit 단어로 보기 보충. < 2 → 문제 생성 안 함(422) | 4지선다 최소 조건 |

## 3. 문제 유형

| 유형 | 프롬프트 예 | 1차 | 비율 |
|---|---|---|---|
| 뜻 → 영어 | '토끼'를 영어로? | ○ | 60% |
| 영어 → 뜻 | rabbit 은 무슨 뜻? | ○ | 40% |
| 예문 빈칸 | The ___ can jump. | 미정 | — |
| 듣고 고르기 | 🔊 → 단어 | 2차 | — |

**결정**: 1차는 위 두 유형, 모두 4지선다(`type: "choice"`). 오답 단어에는 **뜻 → 영어**를 우선 배정 (쓰기 방향이 더 어려워 복습 효과 큼).
**미정**: 예문 빈칸 추가 여부 — 8일차, 문제 생성 안정화 후.

## 4. 보기(choices) 생성

| 규칙 | 결정 |
|---|---|
| 오답 보기 출처 | 같은 Unit 단어 3개 (뜻→영어면 영어, 영어→뜻이면 한국어 뜻) |
| 부족 시 | 같은 Level 다른 Unit → 그래도 부족하면 Gemini에게 "초등 어휘로 그럴듯한 오답 3개" 요청 |
| 정답 위치 | 무작위. 4문제 연속 같은 위치 금지 |
| 헷갈리는 보기 | 1차는 안 함(무작위). 미정: 철자 유사 단어 우선(cat/cap) — 2차 |

## 5. Gemini 호출

| 항목 | 결정 | 근거 |
|---|---|---|
| 역할 분담 | **구성(어떤 단어, 유형, 보기 후보)은 코드가** 정하고, Gemini는 **문장 다듬기 + 검증**만 | 규칙을 프롬프트에 맡기면 지켜지지 않음. 코드가 정하면 오답 반영이 확실 |
| 출력 형식 | `response_schema` 로 JSON 강제 (questions 배열, PRD 5.4 스키마) | 파싱 실패 최소화 |
| 실패 처리 | 1회 재시도 → 그래도 실패면 **코드가 만든 문제 그대로 반환** (Gemini 없이도 성립) | 데모 중 API 장애 대비. 화면의 임시 문제와 같은 원리, 서버에서 |
| 모델 | `.env` 의 GEMINI_MODEL. 느리면 `gemini-3.5-flash-lite` 로 교체 시험 | 30초 문제 |
| 타임아웃 | 25초. 넘으면 실패 처리 | 화면 45초 타임아웃보다 짧게 |

즉 **Gemini가 죽어도 문제는 나온다.** Gemini는 "초등 눈높이 프롬프트 문장"과 "보기 품질"을 올리는 역할.

## 6. 속도 · 캐싱

| 항목 | 결정 |
|---|---|
| 미리 만들기 | 학습 화면 진입 시 화면이 `/quiz?prefetch=1` 호출 → 서버가 생성해 캐시. 문제 화면에서 즉시 사용 |
| 캐시 키 | (student, level, unit, wrong_words 해시). 오답이 바뀌면 새로 생성 |
| 캐시 위치 | 메모리 dict (서버 재시작 시 사라져도 됨) |
| 유효 | 1회 사용 후 폐기 (다시 풀기는 새 문제) |

**미정**: prefetch 파라미터를 PRD 5.4 에 추가할지 (API 변경 → 셋 합의). 5일차.

## 7. 채점 · 기록 (`/answer`)

| 항목 | 결정 |
|---|---|
| 채점 | 서버가 quiz 캐시의 answer 와 비교. 캐시 없으면(재시작) 요청의 choice 만 기록하고 correct=null |
| 오답 기록 | `wrong_words[student][word].count += 1`, `last = 오늘` |
| 정답 시 | 그 단어가 wrong_words 에 있으면 `streak += 1`. **연속 2회 정답이면 삭제** | 복습 완료 판정. count 를 줄이지 않고 지우는 게 단순 |
| 로그 | `quiz_log.jsonl` 한 줄 (PRD 6.2 형식 + quiz 유형, mock 여부) |
| 학생 DB 파일 | `backend/student.py` (팀장). 읽기·쓰기 함수만, API 는 `/progress` 계열 |

## 8. 오답 설명 (`/explain`)

| 항목 | 결정 |
|---|---|
| 입력 | 틀린 문제(단어, 학생 답, 정답) + RAG 조각 1개 (없으면 골든 예문) |
| 출력 형식 | 한국어 2~3문장. 1문장: 뜻, 2문장: 기억 힌트(생김새·소리·예문), 3문장(선택): 학생 답과 비교 | 
| 근거 표시 | `source` 필수. RAG 조각 없으면 골든 words 의 example + source_page 로 대체하고 `source.chunk_id = null` |
| 금지 | 조각·예문에 없는 사실, 영어 문법 용어, 3학년이 모를 한자어 |
| 캐싱 | (word, 학생 답) 단위 메모리 캐시. 같은 오답이면 재호출 없음 |
| 실패 | Gemini 실패 → `explanation: "{word}은/는 '{meaning}'이에요. 예문: {example}"` 규칙 문장 반환 |

## 9. 프롬프트 파일 (`backend/prompts/`)

| 파일 | 변수 | 비고 |
|---|---|---|
| `quiz.txt` | {{level}} {{unit}} {{words}} {{priority_words}} {{chunks}} {{count}} {{types}} | 출력 스키마는 코드에서 붙임 |
| `explain.txt` | {{word}} {{meaning}} {{student_answer}} {{chunk}} {{example}} {{page}} | |

파일은 매 호출 읽는다(수정 즉시 반영). 프롬프트 다듬기는 코드 없이 이 파일만.
