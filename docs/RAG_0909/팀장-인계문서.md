## 전달 메시지 

```
[RAG] /fix RAG 연결 붙일 준비 됐습니다 🙋

검색 실제로 동작해서 tutor.py의 _search_rule() 스텁만 바꾸면 mode="rag"로 전환됩니다.
인계 문서: docs/RAG_0909/팀장-인계문서.md (5분 분량)

핵심만 먼저 말씀드리면:
1. HTTP 재호출 말고 `from backend.rag import search_rules` 직접 import해서 쓰시면 됩니다
   (색인 없을 때뿐 아니라 임베딩·질의 실패까지 전부 `indexing.IndexUnavailableError`
   하나로 정규화되니, 이 예외 하나만 캐치하시면 됩니다 — 코드 리뷰로 발견해서 수정 완료)
2. ⚠ 임계값(threshold)은 이번엔 켜지 마세요 — 실측해보니 정상 문장(오류 없음)이
   오류 문장보다 검색 점수가 더 높게 나와요(평균 0.415 vs 0.317). "점수 낮으면 정상"
   가정이 지금 데이터에선 반대라, ok 판단은 그대로 Gemini한테 맡기시는 게 안전합니다.
3. 근거 밖 ID를 ok=true로 처리하는 현재 로직도 같이 봐주시면 좋겠습니다 (문서 4번 항목)
4. 화면 버그 하나 더요 — 진단 카드가 mode 상관없이 항상 "📚 RAG가 찾은 근거"라고 뜹니다.
   폴백 모드에서도 이 문구가 그대로 나와서 그 아래 폴백 안내 배지랑 서로 모순돼 보여요.
   실제로 앱 띄워서 확인했습니다 (문서 5번 항목)

현재 검색 품질은 _sample-B(개발용 규칙 8개) 기준 hit@3 75%로 목표(80%) 살짝 못 미치는
상태인데, 일단 이대로 연결 진행하기로 했고 데이터팀 정식 납품 후 재측정할 예정입니다.

반영하신 뒤에 저한테 알려주시면 통합 검증(정상문장 오교정·장애처리 등) 같이 확인하겠습니다.
그리고 그때 기록 안 남기는 내부 함수(fix_internal()) 하나 필요한데 문서 6번에 시그니처
제안해뒀어요 — 검토 부탁드립니다.
```

## 상세 인계 내용

### 1. 호출 방법

```python
from backend.rag import search_rules
from backend import indexing

try:
    candidates = search_rules(text, k=3)   # 상위 3개, score 내림차순
except indexing.IndexUnavailableError:
    candidates = []   # 색인 없음/임베딩 실패/질의 실패 등 검색 관련 모든 실패 → 전체 규칙(golden.rules())으로 폴백
```
검색 과정(컬렉션 접근·임베딩·질의) 중 어디서 실패하든 전부 이 예외 하나로 정규화됩니다 — 위 `except` 한 줄로 모든 검색 실패 케이스가 커버됩니다(코드 리뷰에서 임베딩·질의 실패가 안 잡히던 걸 발견해서 수정 완료).

- **HTTP로 `/api/rag/search`를 다시 부르지 마세요.** 같은 프로세스 안에서 함수 직접 호출이면 충분합니다(API는 이 함수를 감싼 래퍼일 뿐입니다).
- 반환값 형식: `[{"id":"R-01","type":"과거시제","text":"원본 규칙 전문...","unit":"U3","score":0.4367}, ...]`
- `score = 1 - cosine_distance` (높을수록 관련 있음). 저장 건수(현재 8개)보다 많은 `k`를 줘도 초과 반환 안 함.
- 호출 속도: 로컬 모델이라 외부 API 아님, 수십 ms. 프로세스 첫 호출만 모델 로딩으로 조금 느릴 수 있음(선택: 서버 기동 시 한 번 미리 호출해도 됨, 필수는 아님).

### 2. `/fix` 필드에 이렇게 채우면 됩니다

| 필드 | 값 |
|---|---|
| `rule` | `candidates[0]` 있으면 `{"id":c["id"], "name":c["type"], "score":c["score"]}`, 없으면 `null` |
| `runner_up` | `candidates[1]` 있으면 같은 형식, 없으면 `null` |
| `source` | `{"chunk_id":candidates[0]["id"], "text":candidates[0]["text"]}` — **Gemini가 만든 출처 말고 서버가 전달한 후보에서 그대로 구성** |
| `mode` | 검색 성공(예외 없음) → `"rag"`. 예외 발생 → `"fallback"` |
| `fallback_reason` | `mode="fallback"`일 때만 `"search_error"` (현재 threshold 미설정이라 이 사유만 발생) |
| 프롬프트 근거 | 최초 기준선: `candidates[0]` 1개만 전달. `fallback`이면 기존처럼 `golden.rules()` 전체 |

### 3. ⚠ 임계값(threshold)을 지금 켜면 역효과 — 실측 근거

`_sample-B` 8개로 검색 1위 점수를 실제로 재봤습니다.

| 구분 | 1위 점수 | 평균 |
|---|---|---|
| 오류 문장(정답 맞힘) | 0.236 ~ 0.366 | 0.317 |
| **정상 문장(오류 없음)** | **0.381 ~ 0.449** | **0.415** |

**정상 문장이 오류 문장보다 검색 점수가 더 높게 나옵니다.** "점수가 낮으면 정상 문장"이라는 PRD 원안의 가정이 지금은 반대로 나타납니다. 그래서:

- **`score < threshold`로 "정상 문장(ok=true)"을 판정하지 마세요.** 오히려 정상 문장을 오류로 몰아갈 수 있습니다.
- "오류가 있는지"는 검색 점수가 아니라 **Gemini의 판단(`ok` 필드)에 맡기는 걸 권장**합니다. 검색은 "1위 근거를 골라주는 역할"만 하고, 실제 위반 여부는 프롬프트·생성이 판단하게 두세요.
- threshold는 최초 기준선에서 미설정(`null`) 유지 — 정식 데이터(25개) 들어오면 그때 다시 봅니다.

### 4. 시험해보시면 좋은 사례

| 사례 | 어떻게 | 기대 동작 |
|---|---|---|
| 정상 검색 | `"I go to the zoo yesterday"` | 1위 `R-01`, score 0.4367, `mode="rag"` |
| 색인 장애 | `data/chroma/manifest.json`을 임시로 옮기고 호출 | `IndexUnavailableError` → 전체 규칙 폴백, `mode="fallback"`, `fallback_reason="search_error"` |
| 검색 도중 장애(임베딩·질의 실패) | (참고용, 재현 어려움) 임베딩 함수가 예외를 던지는 상황 | 마찬가지로 `IndexUnavailableError`로 정규화되어 위와 동일하게 폴백됨 — 코드 리뷰로 발견해 수정 완료(수정 전엔 이 경우 원본 예외가 그대로 새서 `/fix`가 죽었을 것) |
| 근거 밖 ID | Gemini가 `candidates`에 없는 `rule_id`를 응답에 넣은 경우 | **현재 버그**: 전체 목록에 있는지만 확인해서 `ok=true`로 처리해버림. 실제 전달한 `candidates` 안에 있는지까지 검증해서, 없으면 502로 바꿔주세요 |

### 5. 화면 버그 — 근거 배지 문구가 실제 mode와 안 맞습니다

`tutor.js`의 진단 카드가 `mode`와 상관없이 항상 **"📚 RAG가 찾은 근거"**라고 표시합니다:

```js
d.innerHTML = `...<div class="src">📚 <b>RAG가 찾은 근거</b> · ${esc(r.source?.chunk_id || '')}...`
```

그 아래에 mode별 작은 안내 배지(`서버 /fix · 규칙 전체를 Gemini에 넣는 폴백 모드 (RAG 검색 연결 전)` 등)가 따로 붙긴 하지만, **바로 위 큰 제목은 fallback 모드에서도 "RAG가 찾은 근거"라고 말해버립니다.** 실제로 지금(폴백 모드) 화면을 띄워보면 이렇게 보입니다:

```
📚 RAG가 찾은 근거 · R-01
어제(yesterday)... (규칙 본문)
서버 /fix · 규칙 전체를 Gemini에 넣는 폴백 모드 (RAG 검색 연결 전)
```

윗줄과 아랫줄이 서로 모순됩니다. `mode="rag"`일 때만 "RAG가 찾은 근거"라고 하고, `mode="fallback"`일 때는 "전체 규칙 중 하나"처럼 다르게 표현해주시면 좋겠습니다(v0.2 work order §9에도 같은 내용이 있던 항목인데, 이번에 실제 화면에서 문구까지 확인했습니다).

### 6. ④-C(통합 검증)를 위해 부탁드리는 것 — 기록 없는 내부 함수

정상 문장 오교정 등을 평가할 때 학생 기록(`sentence_log.jsonl`·`notebook.json`)을 남기면 안 되니, 아래 같은 함수 하나를 추가해주시면 좋겠습니다.

```python
# backend/tutor.py 제안
def fix_internal(text: str, level: int = 2, unit: str = "") -> dict:
    """POST /fix 와 같은 로직이되 _log_sentence()/_notebook_add() 를 호출하지 않는다.
    반환 형식은 POST /fix 응답과 동일."""
```

이게 생기면 저희 쪽 `tests/eval_rag.py`에 `--with-generation` 옵션을 추가해서 생성 평가까지 자동화할 수 있습니다.
