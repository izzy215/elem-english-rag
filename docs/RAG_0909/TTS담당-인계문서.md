## 상세 인계 내용

### 이번 RAG 작업 범위에 `/ask` 연결은 포함되지 않습니다

`docs/rag-implementation-work-order_v0.2.md` 2절이 `ask.py` 수정을 이번 범위에서 명시적으로 제외해뒀습니다. 그래서 RAG 담당은 `ask.py`를 고치지 않았고, 앞으로도 직접 고치지 않습니다. 이 문서는 **"지금 당장 뭘 쓸 수 있고, 뭐가 더 필요한지"를 TTS 담당께 알려드리는 참고 자료**입니다 — 연결 여부·시기는 TTS 담당 판단입니다.

### 1. 지금 `ask.py`가 실제로 하는 일 (코드로 확인함)

```
질문 도착
  → "맞는 문장이에요?" 류 정규식 매칭되면: _check_correctness() → golden.rules() 전체를 프롬프트에 넣고 Gemini 판정
  → 아니면: _local_match() 단어겹침(1순위 faq.jsonl, 2순위 rules.jsonl) 시도
      → 매칭 성공(점수≥0.5): Gemini 호출 없이 바로 반환
      → 실패: _faq_block(전체 faq.jsonl)을 프롬프트에 통째로 넣어 Gemini 호출
```
`ask.py` 자체 주석에 "`rag.search` 완성되면 1위 조각만 넣는 방식으로 바꿀 수 있음"이라고 이미 적혀 있던 부분입니다.

### 2. 지금 당장 연결 가능한 것 — 규칙(rules) 검색만

`backend.rag.search_rules(text, k=3)`가 실제로 동작합니다. **단, `rules.jsonl`(문법 규칙)만 색인돼 있고 `faq.jsonl`은 색인 안 돼 있습니다.**

바꿀 수 있는 부분은 `_check_correctness()`뿐입니다 — 지금 `golden.rules()` 전체(8개)를 프롬프트에 넣는데, `tutor.py`의 예전 폴백 모드와 똑같은 패턴입니다. `search_rules(question, k=3)`의 1위 결과만 넣는 방식으로 바꾸면 `tutor.py` 연결과 같은 구조가 됩니다. 호출 방법·예외 처리·주의사항(임계값 위험 포함)은 [팀장-인계문서.md](팀장-인계문서.md)와 동일하니 그쪽을 참고하시면 됩니다.

### 3. 지금 안 되는 것 — FAQ 검색 (별도 작업 필요)

`_local_match()`가 실패했을 때 `_faq_block(all_faqs)`로 **FAQ 30개(현재 샘플은 6개) 전체를 프롬프트에 넣는 부분**은 지금 방식으로 못 바꿉니다. `faq.jsonl`을 검색하려면:

- `faq.jsonl`을 임베딩해서 **별도 Chroma 컬렉션**(PRD 원안의 `explain` 컬렉션에 해당)을 새로 만들어야 함 — 지금 색인은 `rules.jsonl`만 담고 있어서 재사용 불가
- `search_faq(text, k=3)` 같은 별도 함수가 필요 (`search_rules()`와 별개)

이건 `docs/rag-implementation-work-order_v0.2.md`가 "FAQ 색인과 `/ask` 연결"을 후속 범위로 명시 제외해둔 부분이라, **이번엔 만들지 않았습니다.** 필요하시면 RAG 담당에게 별도로 요청해주시면 됩니다(작업 자체는 지금 `rules.jsonl` 색인 만든 것과 구조가 거의 같아서 규모가 크지 않습니다).

### 4. 참고 — `_check_correctness()`에 검색을 붙이실 때 주의할 점

`tutor.py` 인계 문서에서 이미 짚은 것과 같은 문제입니다: **`_sample-B` 실측에서 정상 문장의 검색 1위 점수(평균 0.415)가 오류 문장(평균 0.317)보다 오히려 높게 나옵니다.** `search_rules()`를 `_check_correctness()`에 연결하실 때, 검색 점수만으로 "이 문장은 맞다/틀리다"를 판단하지 마시고 지금처럼 Gemini의 판정(`ok` 필드)에 맡기는 걸 권장합니다.

---

정리하면: **규칙 관련 질문(`_check_correctness`) 개선은 지금 바로 가능**하고, **FAQ 답변 검색은 별도 색인 작업이 먼저 필요**합니다. 어느 쪽이든 진행하시게 되면 알려주세요.
