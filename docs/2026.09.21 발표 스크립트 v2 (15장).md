## 예상 질문 (짧은 답)

- **왜 RAG 가 필요한가, 규칙 100개면 그냥 프롬프트에 다 넣으면 되지 않나?** → 실제로 그렇게 해 봤습니다. 규칙 100개를 다 주면 71, 검색으로 8개만 주면 85.7 입니다. 후보를 좁혀 줘야 모델이 잘 고릅니다. (8장)
- **정확도 85.7 은 높은 건가?** → 검색이 정답을 8개 안에 넣어 주는 게 93% 이고, 그 안에서 모델이 고르는 게 85.7 입니다. 남은 실패는 이웃 규칙 선택 15건, 맞는 문장이라고 한 16건 정도이고, 시험지 자체가 애매한 것도 9건쯤 됩니다.
- **모델이 틀린 걸 어떻게 막나?** → 검증기 10가지 검사입니다. 모델이 고친 단어가 학생 문장에 실제로 있는지, 뜻을 바꾸지 않았는지, 고른 규칙이 검색 후보 안에 있는지. 걸리면 한 번 더 묻고, 그래도 안 되면 "교과서 표현으로 다시 말해 볼까요"로 안내합니다.
- **임베딩은 왜 1위 모델을 안 쓰나?** → gemini 는 API 키와 한도가 필요합니다. 교실 GPU 의 e5-base 는 무제한이고 4.6점 차이라 운영은 e5-base 로 했습니다.
- **STT 완전 동일이 13.7% 면 낮은 것 아닌가?** → 부분 동일 77% 는 조사·띄어쓰기 차이입니다. 뜻이 통하는 건 90.7% 이고, 완전 동일이 낮은 이유는 반말이 존댓말로 바뀌는 남은 버그입니다.
- **아이 목소리로 재 봤나?** → 깨끗한 영어는 합성음으로, 섞인 말도 합성음으로 쟀습니다. 실제 아이 녹음은 서비스 로그로 쌓이기 시작했고 같은 도구로 잴 수 있습니다.
- **BigQuery 는 어디에 썼나?** → 관리자 주간 리포트입니다. 학생 문장 로그를 올려 SQL 세 개로 집계하고, 없으면 파일 집계로 동작합니다.
