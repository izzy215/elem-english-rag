## 1. 한 줄 정의

> 초등학생이 Unit 미션에 맞춰 **영어 문장을 말하거나 쓰면**, RAG가 우리가 만든 문법 규칙 조각에서 관련 규칙을 찾아 **AI가 근거를 붙여 고쳐주고**, 틀린 규칙이 오답노트에 쌓여 연습으로 이어지는 튜터.

핵심 루프: **표현 익히기 → 내 문장 말하기/쓰기 → RAG 규칙 검색 → 고쳐주기 + 설명 → 오답노트(문법) → 규칙 연습 → 다시 말하기**

A안과의 차이 한 줄: A는 "단어 4지선다 → 오답 단어 복습", B는 "내 문장 → 문법 규칙 진단". **B에서만 RAG가 진짜 검색을 한다** (학생 문장에는 규칙 라벨이 없으므로).

## 2. 왜 B인가

- **RAG가 필수인 구조.** 학생이 말한 문장은 데이터에 없고 라벨도 없다. 어느 규칙인지 검색으로 찾아야 한다. A안의 "단어 id → 조각"은 DB 조회였다.
- **팀원 작업이 핵심에 들어온다.** STT(완성)가 튜터의 입력, TTS가 패턴 듣기.
- **데이터팀 샘플과 일치.** 그들이 만든 `retrieved_context`가 규칙 조각, `student_error`가 오류 예시.
- **발표 장면이 강하다.** 🎙 말하기 → 검색 점수 → 고침 → 근거. "언제 DB고 언제 RAG인지 구분했다"까지 말할 수 있다.

### 2.1 RAG의 역할 정의 (A·B 공통 전제 → [docs/README](../README.md))

초등 영어는 답이 정해져 있다. 고정되지 않은 것은 **질문**(학생이 쓴 문장, 삐뚤빼뚤한 물음)이다.
- **깔때기**: 라벨 없는 학생 문장 → 올바른 규칙 조각. hit@3 가 재는 것.
- **목줄**: 고쳐주기·설명은 검색된 조각 안에서만. 아이에게 틀린 문법을 가르치지 않기 위한 보증.
- 한계: 이 규모에선 키워드 검색과 차이가 작을 수 있음. 발표 문장 — *"닫힌 도메인에서 RAG의 역할은 지식 확장이 아니라 질문 흡수와 근거 보증이다."*
- 로드맵: 열린 문제(자유 작문 첨삭)는 다음 단계.

## 4. 1차 범위

| 기능 | 1차 | 비고 |
|---|---|---|
| Level · Unit 선택 | ○ | Unit = 말하기 미션 ("동물원에서 본 것") |
| 표현 익히기 | ○ | 단어 8 (가로 스크롤) + 문장 패턴 3 (규칙 힌트 한 줄) + 듣기 |
| **내 문장 말하기 / 쓰기** | ○ | 🎙 STT 또는 ⌨ 입력. 핵심 화면 |
| **RAG 규칙 검색** | ○ | 학생 문장 → 규칙 조각 상위 3 + 점수. 점수 기준 미만이면 "걸리는 규칙 없음" |
| **고쳐주기 + 설명** | ○ | 찾은 규칙만 근거로 Gemini가 고침 · 초등 눈높이 2문장 · 근거 표시 |
| 더 물어보기 | ○ | 추천 질문 버튼 3 + 직접 입력. 질문 → 설명 조각 검색 → 답 (RAG 입구 2) |
| 오답노트 (문법 규칙) | ○ | 규칙별 횟수 · 내 문장 · 고친 문장 · 근거. 연속 2회 정답이면 극복 |
| 규칙 연습 | ○ | 4지선다 "고칠 말 고르기" 2문제. 기존 문제 화면 재사용 |
| 듣기 (TTS) | ○ | 패턴 · 고친 문장 듣기 (완성된 tts.py) |
| 말하기 입력 (STT) | ○ | 완성된 speak.py 재사용. 채점이 아니라 **입력** 용도 |
| 관리자 | ○ | 데이터 상태 · RAG 정확도(문장→규칙) · 학생 문장 로그 |
| 단어 4지선다 문제 | △ | 규칙 연습으로 축소. 단어 퀴즈는 시간 남으면 |
| 소스 등록 · 검수 경고 | ✕ | 자체 제작이라 데이터팀이 파일로 관리 |
| 로그인 · 발음 채점 · XP | ✕ | |

## 6. 시스템 구성

```
브라우저 (HTML + JS, 화면별 파일)
   │ /api/...
FastAPI
   ├─ golden.py    levels · units · words · patterns          TTS 담당
   ├─ rag.py       규칙 조각 임베딩 → Chroma → /rag/search     RAG 담당  ★
   ├─ tutor.py     /fix (검색 + 프롬프트 + Gemini) · /ask       팀장     ★
   ├─ student.py   오답노트 · 문장 로그 · /notebook              팀장
   ├─ drill.py     규칙 연습 문제 · /drill · /answer            팀장
   ├─ tts.py · speak.py                                       TTS 담당 (완성)
   └─ eval (tests/)  문장→규칙 hit@3                           RAG 담당
데이터
   ├─ 골든 (데이터팀 자체 제작): rules.jsonl ★ · words · patterns · errors.jsonl · eval.csv
   ├─ 학생 DB (JSON): notebook.json · sentence_log.jsonl
   ├─ Chroma (data/chroma/): rules 임베딩
   └─ 음원 캐시
```

**RAG가 일하는 곳 두 군데**: ① `/fix` 안의 문장 → 규칙 검색 ② `/ask` 안의 질문 → 설명 조각 검색. 그 외(오답노트 조회, 패턴 표시)는 id 조회이며 RAG라 부르지 않는다.

## 7. 데이터 — 자체 제작

교과서 없음. 데이터팀이 **규칙 조각을 직접 쓴다.** 참고자료(NCIC 어휘 목록 등)는 단어 범위 체크용.

| 파일 | 내용 | 1차 목표 | 역할 |
|---|---|---|---|
| `rules.jsonl` ★ | 문법 규칙 설명 조각 (유형 6 × 상황별 3~5) | 25 | RAG 검색 대상 = "교재" |
| `words.csv` | 단어 · 뜻 · 예문 · Unit | 40 | 표현 익히기 |
| `patterns.csv` | 문장 패턴 · 뜻 · 규칙 힌트 · Unit | 20 | 표현 익히기 · 듣기 |
| `errors.jsonl` | 오류 문장 · 정답 · 유형 · 규칙 id | 40 | 규칙 연습 · 평가 · 데모 |
| `eval.csv` | 학생 문장 → 정답 규칙 조각 id | 30 | RAG 정확도 |

## 10. 성공 기준

- **데모 60초**: Unit 3 → 🎙 "I go to the zoo yesterday" → 고쳐줘 → 3단계 → "went" + 근거(점수 0.91) → "왜 went예요?" → 답 → 오답노트에 과거시제 → 학생 B로 바꾸면 비어 있음
- **숫자**: 평가셋 30문장 기준 **문장 → 규칙 hit@3 ≥ 80%**, 조각 조립 방식 3종 비교 그래프
- **구분 설명**: "여기는 DB 조회, 여기는 RAG"를 발표에서 명시
