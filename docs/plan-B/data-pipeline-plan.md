## 1. 파이프라인 (6단계 · 순서가 A안과 다름)

```
참고자료 ─▶ ① 범위: 유형 6 · Unit 3 ─▶ ② 규칙 조각 쓰기 ★ ─▶ ③ 오류 예시 + 평가셋 ─▶ ④ 패턴 · 단어 ─▶ ⑤ 검수 ─▶ ⑥ 납품 · 조립 실험
```

### ① 범위 — 데이터팀 + 팀장 · 1일
- 오류 유형: 계획은 6개였으나 납품본은 **유형 30여 종 · 규칙 38개** (Unit별 30 + 공통 8: 과거시제 R-31 · 관사 R-34/R-38 등). 기준: 초등 6학년이 실제로 틀리는 것, 한 문장에서 딱 보이는 것
- Unit 20 = 말하기 미션 20 (Level 3, Unit01 Greetings ~ Unit20). 미션마다 힌트 단어 5개, 걸릴 규칙 4개
- **출력**: `units.csv` 20줄, 유형 목록

### ② 규칙 조각 쓰기 ★ — 데이터팀 · 2일 (가장 중요)
- 유형마다 **상황별 조각 3~5개**. 예: 과거시제 → "yesterday와 함께" / "불규칙 동사 go·see·eat" / "last week·ago" / "was·were"
- **검색이 잘 되는 조각 쓰는 법** (4절) 을 지켜서 씀
- **방법**: 데이터팀 샘플의 `retrieved_context` 100개를 유형별로 모아 → 겹치는 것 합치고 → 빠진 상황 추가 → Gemini로 초등 말투 다듬기 → 사람 검수
- **출력**: `rules.jsonl` 25줄 (납품은 38줄)
- **끝 기준**: 유형 6 모두 3개 이상 · 각 조각에 예문 2개 + 틀린 예 1개 포함

### ③ 오류 예시 + 평가셋 — 데이터팀 · 2일
- `errors.jsonl` 목표 40 → **납품 400**: 규칙마다 여러 개. 샘플 100개 중 Level 단어인 것 재활용 + Unit 단어로 새로 씀. `target`(틀린 말) · `fix` · `distractors` 3개 (전부 채움)
- `eval.csv` 목표 30 → **납품 72**: **학생이 말할 법한 문장** 65 (errors 와 겹치지 않게) + **정상 문장 7** (expected=NONE). 조각 본문을 베끼지 않는다
- **출력**: 두 파일
- **끝 기준**: errors 의 오류가 실제로 그 규칙 위반 · eval 문장이 조각 문장과 겹치지 않음

### ③-1 FAQ 조각 — 데이터팀 · 1일
- `faq.jsonl` 목표 30 → **납품 74**: 학생이 물을 법한 질문 + 초등 말투 답 2~3문장 + 근거 rule_ids. 샘플의 `feedback` 이 출발점
- 질문 표현은 다양하게 ("왜 went예요", "go 과거가 뭐야") — 챗의 깔때기 실험 재료
- 형식: `id · unit · question(대표) · variants[](같은 뜻 다른 표현 3+) · answer(초등 말투 2~3문장) · rule_ids[] · example`. 구성 안: 규칙 질문 15 · 단어 뜻 10 · 요청형("다른 예문") 5
- 예시와 컬럼 해설: [data/golden/_sample-B/README.md](../../data/golden/_sample-B/README.md)

## 4. 검색이 잘 되는 규칙 조각 쓰는 법 (데이터팀 가이드)

RAG는 **학생 문장과 조각 본문의 의미가 가까운지**로 찾는다. 프롬프트가 아니라 **조각 글**이 검색 품질을 정한다.

| 하기 | 예 |
|---|---|
| 학생이 쓸 법한 **영어 단어를 본문에 넣는다** | yesterday, last week, go, went, zoo |
| **틀린 예 1개**를 본문에 넣는다 (학생 문장은 틀린 문장이므로) | "틀린 예: I go to the zoo yesterday." |
| **맞는 예 2개** | "I went to the zoo yesterday. I saw a lion." |
| 한국어 설명은 **초등 말투 한두 문장** | "지난 일을 말할 때는 동사를 과거형으로 써요" |
| 조각 하나 = **상황 하나** | "yesterday와 함께"와 "불규칙 동사"는 따로 |

| 피하기 | 이유 |
|---|---|
| "과거시제: 동사+ed" 처럼 문법 용어만 | 학생 문장과 겹치는 말이 없어 검색 안 됨 |
| 한 조각에 규칙 여러 개 | 어느 규칙인지 흐려짐 |
| 300자 넘는 긴 조각 | 핵심이 희석됨. 80~200자 |
| Unit과 무관한 예문 | Unit 단어로 쓰면 미션 문장과 더 가까워짐 |

조각 형식:
```
{"id":"R-31","type":"과거시제","unit":"ALL",
 "text":"어제(yesterday), 지난주(last week), 아까(ago)처럼 지난 일을 말할 때는 동사를 과거형으로 써요. go는 went, see는 saw, eat는 ate가 돼요. 예: I went to the zoo yesterday. I saw a lion. 틀린 예: I go to the zoo yesterday.",
 "short":"과거를 말할 땐 동사를 과거형으로",
 "examples":["I went to the zoo yesterday.","I saw a lion."],
 "wrong_example":"I go to the zoo yesterday."}
```
(납품본 실제 줄. unit 은 Unit01~Unit20 또는 여러 Unit 공통이면 "ALL". R-01 은 형용사+be동사 · Unit01)
