관리자 · 쉬운 말로

한 줄. 관리자 화면은 "우리 서비스가 지금 얼마나 맞나"를 시험지로 채점해 보여 주는 곳이에요. 학생 화면이 아니라 팀·교수님·심사위원용.
  1. 시험지 = eval.csv. 문장 360개에 "정답 규칙" 이 적혀 있어요 (틀린 문장 300 + 맞는 문장 60). 서비스는 이 파일을 절대 읽지 않아요.
  2. ② 규칙 찾기 정확도 — 검색 단계만 채점. "정답 규칙이 후보 3개 안에 들어왔나" = hit@3. 1위면 hit@1, 5개 안이면 hit@5. 튜터는 후보 5개를 받으니 hit@5 가 튜터의 상한.
  3. ③ 튜터 정확도 — 끝까지 채점. 학생이 실제로 받는 답 기준. 두 숫자를 같이 봐요: 틀린 문장을 맞는 규칙으로 고쳤나(규칙 정답률) + 맞는 문장을 안 건드렸나(정상 유지율). 한쪽만 올리기는 쉬워서 둘 다 봐야 해요.
  4. ④ 챗봇 정확도 — ③과 같은 방식으로 /ask 를 채점. 시험지는 FAQ 130개의 질문 변형 + 엉뚱한 질문 20개. "맞는 FAQ 로 답했나", "엉뚱한 질문은 거절했나". (tests/eval_ask.py, 예정)
  5. ②와 ③이 다른 이유 — ②가 91% 인데 ③이 61% 면, 후보엔 정답이 있었는데 모델이 딴 걸 고르거나 검증기가 막은 것. 9/11 실측이 딱 그 경우(검증기가 12개를 규칙 밖으로 돌림).
  6. 실행 버튼 — 모델·조건을 바꿔 같은 시험지를 다시 채점해요. 결과는 표에 한 줄씩 쌓이고, 시험지가 바뀌면 옛 줄은 숨겨요(짝이 안 맞는 비교 방지).
  7. ⑤ 교과서 검색 시험 — 숫자가 아니라 눈으로 보는 곳. 문장을 넣으면 검색 ③이 뭘 가져오는지.
  8. ⑥ 학생 로그 — 실제 사용 기록. 어느 규칙이 많이 걸리나(수업 자료), 규칙 밖으로 빠진 문장(데이터팀이 규칙 추가할 후보). 생성 점검은 학생이 없을 때 모델이 학생 문장을 만들어 같은 걸 미리 보는 것.
  9. ⑦ 받아쓰기(STT) — 튜터와 별개. 아이 목소리를 글자로 잘 바꾸나.
검색이 진짜 일하는 곳 ② 규칙 찾기(틀린 예문 + 설명문) · ⑤ 교과서 표현 · ④ 챗봇 FAQ. 단어 카드·오답노트 목록은 그냥 파일 읽기라 검색이 아니에요.
확인 필요 ④ 챗봇 시험지(질문 변형 130 + 엉뚱한 질문 20)를 데이터팀이 만들지, faq.jsonl 의 variants 열로 대신할지 (기본안: variants 로 시작).
