관리자 · 기획 포인트

  1. 데이터의 주인공이 바뀜. rules.jsonl(규칙 설명 조각)이 RAG 검색 대상이자 "교재". 단어·패턴은 조연.
  2. 정확도 시험이 의미 있어짐. "이 문장이 어느 규칙에 걸리나"는 id가 없어서 검색으로만 답할 수 있음. 조각 조립 방식(규칙만 / +예시 / +한국어)을 비교.
  3. 학생 문장 로그가 자연스럽게 쌓임 → BigQuery 집계 후보 (수업 요건).
  4. STT 정확도 패널 — TTS 담당의 자체 STT 실험을 Gemini와 같은 잣대(WER)로 비교. 발표에서 "비교해 봤다"까지 말할 수 있음.
RAG가 진짜 일하는 곳 ① 학생 문장 → 규칙 찾기 ② 더 물어보기 → 설명 조각 찾기. 단어 카드·오답노트 조회는 id 조회(DB)이며 RAG라고 부르지 않는다.
확인 필요 소스 등록(검수 경고) 화면을 B에서도 유지할지. 자체 제작이면 데이터팀이 파일로 관리하므로 화면 없이 가도 됨 (기본안: 없음).
