# RAG 담당 요청 — 교과서(패턴·단어) 색인과 검색 함수

작성 2026-09-14 · 팀장 · 대상 파일: `backend/indexing.py`, `backend/rag.py` (RAG 담당 소유) · 받는 쪽: `backend/tutor.py` (팀장)
배경: 교수님 지적 "지금 /fix 의 RAG 는 RAG 가 아니다" — 문법 규칙은 모델이 이미 알아서 검색이 지식을 보태지 않는다. 대응 1(설명을 검색된 규칙 문서에서 가져오기)은 9/14 tutor.py 에 반영. 이 문서는 **대응 2: 모델이 모르는 우리 교과서 자료(패턴 462 · 단어 400)를 검색해 넣기**의 RAG 쪽 작업이다.

## 0. 한 줄

`patterns.csv` 와 `words.csv` 를 규칙 색인과 **별도 컬렉션**으로 색인하고, 학생 문장에 가까운 패턴·단어를 학년 조건으로 돌려주는 `search_textbook()` 하나를 rag.py 에 만들어 달라. tutor.py 는 그 결과 8개쯤을 프롬프트에 "교과서 표현" 으로 넣는다.

## 1. 색인 (indexing.py)

| 항목 | 요청 |
|---|---|
| 컬렉션 | 규칙 색인(`rules_*`)과 별개. 이름 접두사 `textbook_`. 규칙 색인 재생성과 서로 영향 없게 |
| 문서 | patterns.csv 462행: 문서 본문 = `text` (영어 문장만. 뜻·tip 은 메타데이터) · words.csv 400행: 본문 = `word` + " — " + `example` (단어만 넣으면 벡터가 빈약함) |
| 메타데이터 | `kind`(pattern/word) · `id` · `level`(정수) · `unit` · `rule_id`(패턴만) · `meaning` · `tip`(패턴) |
| 임베딩 | 규칙 색인과 같은 `embedding.embed_documents()` — .env 의 EMBEDDING_BACKEND 를 그대로 따름. 색인 manifest 에 규칙 색인처럼 provider·model·dim·count·data_hash 기록 (`manifest.json` 에 `textbook` 키로 넣거나 별도 `textbook_manifest.json`) |
| 명령 | `python -m backend.indexing --rebuild-textbook` (또는 `--rebuild` 가 둘 다 만들기). `--validate-only` 에 두 CSV 의 참조 무결성(level 3~6, unit 존재, rule_id 존재) 포함 |
| 원자성 | 규칙 색인과 같은 방식(새 컬렉션 만들고 manifest 교체 뒤 옛 것 삭제) |

## 2. 검색 (rag.py)

```python
def search_textbook(text: str, level: int, k_pattern: int = 3, k_word: int = 5, min_score: float = 0.0) -> dict:
    """학생 문장에 가까운 교과서 패턴·단어. level 이하만 (학년 밖 자료는 안 줌).
    반환 {"patterns": [{id, text, meaning, tip, rule_id, unit, level, score}], "words": [{id, word, meaning, example, unit, level, score}],
          "query_ms": int}
    색인이 없거나 실패하면 빈 목록 반환 (예외로 /fix 를 막지 않는다 — 규칙 검색과 달리 이건 있으면 좋은 힌트)."""
```

- `level` 필터는 Chroma `where={"level": {"$lte": level}}` 로. 유닛 필터는 두지 않는다 (다른 유닛의 표현도 힌트가 됨).
- `min_score` 아래는 버린다. 기본값은 실측 뒤 정하자 — 엉뚱한 문장("My robot eats pizza on the moon.")에 관련 없는 패턴이 붙지 않게 하는 문턱. `tests/eval_rag.py` 에 `--textbook` 옵션으로 score 분포를 찍어 주면 팀장이 정한다.
- 질의 벡터: 규칙 검색과 같은 문장을 두 번 임베딩하지 않게, `embed_query()` 한 번의 벡터를 두 컬렉션에 쓰는 형태면 더 좋다 (예: `search_all(text, level)` 이 규칙 + 교과서를 한 번에 돌려주기). 필수는 아님 — 로컬 e5 면 한 번 더 임베딩해도 수십 ms.

## 3. 팀장이 이어서 하는 것 (tutor.py · 프롬프트 · 화면)

- /fix: `search_textbook()` 결과를 프롬프트 "교과서 표현" 블록에 넣는다 ("고칠 때 아래 표현·단어가 맞으면 우선 쓰라". 힌트이지 강제가 아님).
- 고친 문장의 단어를 words.csv(학년 이하)와 대조해 학년 밖 단어를 **표시만** 한다 (막지 않음).
- 화면 근거 박스에 "교과서 검색: 패턴 n · 단어 n" 줄, 관리자에 "교과서 표현을 쓴 고침 비율".
- 평가: 같은 120문장을 교과서 검색 있음/없음으로 돌려 **학년 밖 단어 비율**과 **교과서 패턴 사용 비율** 비교 → 검색이 없으면 못 하는 일이라는 근거 (교수님용).

## 5. 참고

- 지금 .env 는 `EMBEDDING_BACKEND=remote` 인데 강의실 임베딩 서버의 e5 모델이 500 을 냈다 (9/11). 규칙 색인은 로컬 e5 로 만들어져 있음. 색인 만들 때 백엔드를 맞춰 달라.
- Gemini 임베딩 무료 한도 하루 1,000회 — 862건 색인은 배치 호출이라 20회 안쪽이지만 한도 잔량 확인.
- 단어 색인은 "단어 하나" 문서라 벡터가 약하다. 예문을 붙이는 이유. 실측에서 단어 검색이 쓸모없으면 패턴만 남겨도 된다.
- 관련: `docs/rag-implementation-work-order.md`, 팀장 메모 `sample/notes/튜터평가-120문장-0911.md`

## 6. 9/14 오전 추가 — 프로토타입이 있음 (backend/textbook.py, 팀장)

RAG 담당 일정이 잡히기 전에 "될지" 만 확인하려고 별도 모듈로 만들어 봤다. **indexing.py·rag.py 는 안 건드렸고**, 임베딩은 embedding.py 함수를 그대로 부른다.
합칠 때 참고용이고, 그대로 써도 된다. 결과:

| 확인 | 결과 |
|---|---|
| 색인 | 862건 (패턴 462 · 단어 400), 로컬 e5-base, 컬렉션 `textbook_*`, manifest `data/chroma/textbook_manifest.json` |
| "I go to school by bus." level≤3 | 패턴 0.878 We go to school by bus. · 0.871 I go by bus. / 단어 0.916 bus · 0.857 car |
| "I have many rice." level≤3 | 패턴 0.909 I have much rice. (정답 표현이 1위) |
| 학년 필터 | level≤6 으로 물으면 L5 uniform 이 올라오고 level≤3 에선 안 나옴 — 동작함 |
| 엉뚱한 문장 "My robot eats pizza on the moon." | 패턴 최고 0.842 (I would like some pizza.) — 교과서 문장(0.88~0.91)과 차이가 작아 문턱은 0.86 안팎에서 실측으로 정해야 함 |
| 검색 시간 | 150ms (서버 안, 모델 캐시된 뒤) |

**발견한 버그**: `golden.all_patterns()/all_words()` 가 units.csv 에 있는 레벨(3학년뿐)만 돌아서 4~6학년 자료 623건이 빠진다. 프로토타입은 CSV 를 직접 읽어 우회했다. 근본 해결은 데이터팀이 units.csv 에 4·5·6 행을 넣는 것 (챗봇·학습 화면도 같은 이유로 300단어가 안 보임).
