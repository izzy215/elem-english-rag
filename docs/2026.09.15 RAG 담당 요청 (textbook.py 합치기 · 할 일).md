# RAG 담당 요청 (2026-09-15) — textbook.py 를 indexing.py / rag.py 에 합치기, 그다음 할 일

작성 팀장 · 대상 RAG 담당 · 9/14 아침 요청서(교과서 색인 만들기)는 이 문서로 대체. 그 색인은 팀장이 `backend/textbook.py` 로 이미 만들어 서비스에 붙어 있다.

## 1. 한 줄

지금 색인 코드가 두 갈래다. **규칙 색인은 indexing.py(만들기) + rag.py(찾기)**, 나머지 네 색인(교과서·틀린 예문·FAQ·규칙 별칭)은 **textbook.py 한 파일**에 만들기와 찾기가 같이 있다. 이걸 한 갈래로 합쳐 달라. **만드는 코드는 indexing.py 로, 찾는 코드는 rag.py 로.** 함수 이름·인자·반환 형식은 그대로(계약 문서 1절), textbook.py 는 없앤다.

## 2. 왜

- 색인 다시 만드는 명령이 두 번(`indexing --rebuild`, `textbook --rebuild`)이라 팀원이 하나만 돌리고 "검색이 이상하다"가 반복된다.
- 매니페스트가 두 방식(규칙은 `manifest.json`, 나머지는 `<kind>_manifest.json`)이라 관리자 화면·유효성 검사가 따로 논다.
- "검색은 RAG 담당" 인데 검색 함수 대부분이 팀장 파일에 있어 담당이 헷갈린다.

## 3. 무엇이 어디로 가나

지금 textbook.py 안에 있는 것과 갈 곳:

| 지금 (textbook.py) | 하는 일 | 갈 곳 |
|---|---|---|
| `_KINDS`, `TEXT_VERSION` | 색인 4종의 컬렉션 접두사·매니페스트 경로 | indexing.py — 규칙(`rules_`, `manifest.json`)도 같은 표에 넣어 **5종 한 표** |
| `_docs_textbook / _docs_examples / _docs_faq / _docs_rulealias`, `_DOCS` | 파일의 어느 열을 문서로 만드나 | indexing.py — 규칙(`text` 그대로)도 `_docs_rules` 로 같은 모양 |
| `build_index(kind)`, `load_manifest(kind)`, `_data_hash` | 임베딩 → 컬렉션 만들기 → 매니페스트 원자적 교체 → 옛 컬렉션 삭제 | indexing.py — 지금 규칙 전용 `build_index()` 를 이걸로 대체 (`kind="rules"`) |
| `_query(kind, qvec, k, where)` | 매니페스트의 컬렉션에서 가까운 것 k개 | rag.py (검색의 바닥 함수) |
| `search_textbook`, `search_examples`, `similar_examples`, `merge_candidates`, `search_faq`, `search_rule_aliases` | 검색 6개 | rag.py — 기존 `search_rules` 옆에 |
| `faq_hit`, `sharp`, `rule_hit` | "뚜렷한 게 있나" 판정 | rag.py |
| `known_words(level)` | 학년 이하 교과서 낱말 (검색 아님, 후검사용) | golden.py 가 자연스럽지만 golden.py 는 다른 팀원 파일 → rag.py 에 두어도 됨 |
| CLI `--rebuild-*`, `--search/--examples/--faq/--rule` | 확인용 | indexing.py(`--rebuild` 한 번에 5개), rag.py(검색 확인) |

## 4. 절대 바꾸면 안 되는 것

- **함수 이름·인자·반환 키** (계약 문서 `docs/2026.09.14 검색 함수 계약 …md` 1절). tutor.py(7곳)·ask.py(6곳)·admin.py(7곳)가 이 이름으로 부른다.
- **매니페스트 파일 이름 5개**: `manifest.json`, `textbook_manifest.json`, `examples_manifest.json`, `faq_manifest.json`, `rulealias_manifest.json`. 관리자 화면(`/admin/golden` 색인 배지, `/admin/textbook`)이 읽는다.
- **컬렉션 접두사**: `rules_`, `textbook_`, `examples_`, `faq_`, `rulealias_`. 재생성은 새 이름으로 만들고 옛것을 지우는 방식 유지.
- **임베딩 모델**: 다섯 색인 전부 `intfloat/multilingual-e5-base` (로컬이든 강의실 서버든 같은 모델). 다른 모델로 하나만 다시 만들면 차원이 안 맞아 검색이 깨진다 (9/14 MiniLM 사고).

## 5. 순서 (호출하는 쪽을 안 건드리고 옮기는 법)

1. indexing.py 에 5종 `_KINDS`·`_DOCS`·`build_index(kind)`·`load_manifest(kind)` 를 넣는다. 규칙은 `kind="rules"`, 문서는 지금처럼 `text` 만. 기존 `build_index()`·`load_manifest()` 는 `kind="rules"` 기본값으로 호환.
2. rag.py 에 `_query` 와 검색 6개 + 판정 3개를 옮긴다. `search_rules` 는 그대로.
3. **textbook.py 는 껍데기로 남긴다**: 안에 `from backend.rag import search_textbook, search_examples, … ; from backend.indexing import build_index, load_manifest` 만. 그러면 tutor·ask·admin 은 한 줄도 안 바꾸고 돌아간다.
4. 확인 (아래 6절) 이 다 통과하면, 팀장이 tutor·ask·admin 의 `from backend import textbook` 을 `rag`/`indexing` 으로 바꾸고 껍데기를 지운다. (호출부 3파일은 팀장·TTS 담당 파일이라 RAG 담당이 손대지 않는다.)

## 7. 옮기면서 같이 고쳐 달라는 것

- **rag.py 의 "색인 오래됨" 검사 완화**: 매니페스트 provider(`sentence-transformers-local`)와 서버 provider(`remote-http`)가 달라도 **모델 이름과 차원이 같으면 같은 색인**으로 본다. 지금은 provider 만 달라도 오래됨으로 찍힌다.
- `indexing.validate()` 가 규칙만 검사하는데, 5종 매니페스트 유무·건수·모델 일치까지 보도록.
- 메모리: 이 PC 는 빈 메모리 3GB 아래면 e5-base 로딩에 MemoryError. 재생성은 `HF_ENABLE_PARALLEL_LOADING=false` 로 하나씩. 관리자에서 재생성 버튼을 붙일 거면 서버 프로세스가 이미 올린 모델을 쓰게(subprocess 로 또 올리지 말고).
