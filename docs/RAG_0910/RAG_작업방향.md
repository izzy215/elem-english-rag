## 0. 회의 목표

> 1차로 구축한 RAG가 왜 기대한 문법 규칙을 정확히 검색하지 못하는지 원인을 분석하고, 검색 정확도를 목표 수준인 75% 이상으로 높이기 위한 개선 방향을 정하는 것.

회의 흐름을 보면 목표는 크게 3가지였습니다.

1. **현재 RAG 검색 오류 원인 파악**
   - 왜 정답 Rule 대신 비슷한 다른 Rule을 가져오는지 확인
   - 특히 문장 표면 유사도 때문에 잘못된 규칙이 검색되는 문제 분석
2. **개선 방법 후보 정리**
   - Embedding 모델 변경
   - 다국어 모델 테스트
   - Rule에 `wrong_example` 같은 예문을 함께 Embedding
   - Top-K 1/3/5 비교
3. **평가 기준 유지**
   - `eval`의 정답을 검색 결과에 맞춰 고치는 것이 아니라, RAG가 정답을 찾도록 검색 구조를 개선
   - 최종적으로 정확도 75% 이상 달성 여부 확인

즉 이 회의는 "다음 기능을 무엇으로 만들까?"를 논의한 기획회의가 아니라, **1차 RAG 성능을 진단하고 튜닝 방향을 잡는 기술 점검 회의**에 가깝습니다.

## 1. 회의에서 정의한 문제

RAG 검색이 **"단어가 겹치는 문장"을 가져오지, "문법 구조가 같은 문장"을 가져오지 못하는** 경우가 있음이 실시간 테스트로 확인됨.

- 예시(회의 중 실제 테스트): `"She's wearing a red dress yesterday"`(과거시제 오류 문장)를 넣었더니, 과거시제 규칙이 아니라 `dress`, `wearing` 같은 겹치는 단어 때문에 다른 규칙이 함께 섞여 나옴. k=5로 요청했는데 그보다 더 많은 후보가 뽑힌 것도 확인됨.
- 스펠링 오류 예시에서도 **R-33(명사복수형)이 실제 정답 규칙보다 점수가 더 높게 나와 1위로 뽑힌** 케이스가 나옴(회의 중 R-35/R-34 번호가 오갔으나, 요지는 "정답 규칙이 2위로 밀려남").

### 골든 데이터에 대한 합의

> "이걸 바꾸면은 학생들이 문제를 틀렸으니까 정답을 바꿔주는 거예요." (참석자 1)
> "어쨌든 얘가 정답이니까 왜 이렇게 나왔는지 그 이유를 고민해야 된다." (참석자 2)

**골든 데이터(정답)는 데이터팀이 만든 그대로 유지하고, "왜 검색이 다른 규칙을 뽑았는지" 원인을 분석하는 쪽으로 방향을 잡음.** 정답을 검색 결과에 맞춰 바꾸는 게 아님.

## 2. 실제 사례 — 참고 규칙 목록에 필요한 규칙 자체가 없었던 경우

```
학생 문장: "nice meet you"
RAG 후보(mode=rag): R-02(인사말 문장부호), R-31(과거시제), R-36(be동사일치),
                     R-34(관사), R-03(소유격) + unit 공통 규칙 6개(총 11개)
LLM 판단: rule_id=R-02, wrong="nice", fix="nice!"
```

## 4. 회의에서 논의된 개선 방향

### (1) 임베딩 방식 재검토
- 현재: 규칙 설명 텍스트만 임베딩
- 후보: 규칙 + **롱 이그잼플(예시 문장)**까지 같이 임베딩 — 문법 구조가 비슷한 예문을 더 잘 찾아낼 수 있을 것으로 기대
- ⚠ **패턴(문제 자체, `patterns.csv`)은 절대 임베딩에 넣지 않기로 함** — 정답을 그대로 유출하는 "오픈북"이 되기 때문. 규칙+예시까지만 검토 대상.

### (2) 임베딩 모델 재테스트
- 어제(0908) 시점에 3개 모델을 비교해 1개(현재 Chroma 기본 `all-MiniLM-L6-v2`)를 선택했으나, **그 이후 데이터셋이 8규칙(샘플)→38규칙(실데이터)으로 바뀌었기 때문에 재테스트가 필요**하다는 의견.
- 한국어 설명 텍스트가 섞여 있어 다국어 지원 모델(제미나이 계열 임베딩 등)도 후보로 언급됨.

### (3) Top-K 1/3/5 비교
- 관리자 페이지에서 top-1(hit@1)과 top-3(hit@3) 수치가 각각 다르게 관찰됨(71% vs 88%) — k값에 따라 결과가 크게 갈리므로, k=1/3/5를 나란히 비교해 어느 지점에서 정확도가 확보되는지 볼 필요.

### (4) 원인 분석 우선
- 규칙을 무작정 추가하기보다, **현재 미스 케이스들을 하나하나 분석해서 "왜" 틀린 규칙이 뽑히는지**부터 좁혀나가기로 함(회의 결론).
