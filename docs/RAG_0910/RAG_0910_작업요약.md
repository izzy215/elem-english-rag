## 4. ⚠ 중요 — 새 문장(홀드아웃)에서 확인된 리스크

다른 세션이 골든 데이터에 없던 새 문장 30개(`tests/data/rag_holdout_20260910.json`, 미커밋)를 만들어뒀길래, 지금 실제 서비스 구성(Gemini+안전망)으로 직접 돌려봤습니다:

```
hit@1 = 66.67% (16/24)   hit@3 = 91.67% (22/24)   검색 실패 0건
```

로컬 모델 단독으로는 hit@1 33.33%였던 것과 비교하면 Gemini 전환이 새 문장에도 확실히 도움이 되지만, **목표(75%)엔 아직 못 미칩니다.** 미스 8건 중 눈에 띄는 것:

- `"My uncle sleepy."` (R-01) — 안전망이 안 걸림. 지금 안전망 트리거 단어 목록(26개, `errors.jsonl` 기반)에 **"sleepy"가 없어서**입니다. → 트리거 단어를 데이터에 있는 것만 쓰지 말고 유의어까지 확장하면 바로 개선될 여지가 있습니다(간단한 후속 작업 후보).
- `"The children excited."` (R-01) — 안전망 덕분에 hit@3엔 걸림(순위 4위로 포함), hit@1은 아직 아님.
- 나머지(R-05·R-08·R-38·R-32·R-37)는 골든셋 분석 때와 같은 패턴(내용 단어 민감성) — 모델 한계로 보임.

**결론: "75% 달성"은 기존 평가셋 기준이고, 실제 학생들이 쓸 다양한 새 문장 전반에 대한 보장은 아직 아닙니다.**

## 5. 담당별 다음 액션

### 팀장 (tutor.py)
1. `search_rules()` 반환 계약(id/type/text/unit/score)은 안 바뀌었습니다 — 코드 수정 불필요, `data/chroma/` 재구축만 하시면 됩니다.
2. 검색 안전망으로 후보가 k개보다 1개 더 올 수 있습니다(문서화됨) — 상위 N개만 쓰는 로직이면 영향 없습니다.
3. rate limit(429) 발생 시 `IndexUnavailableError`→폴백으로 이미 처리되지만, 실제로 몇 % 빈도로 발생하는지는 아직 운영 트래픽으로 검증 안 됐습니다.

### 데이터팀
1. **R-08 ⟷ R-05/R-12, R-17 ⟷ R-35**: 예문을 늘려도 안 고쳐지는, 규칙 개념 자체가 겹치는 문제로 확인됐습니다. 규칙 구분 기준 재검토 필요.
2. `"That is my dog toy."`(R-03 평가 의도) 등 일부 평가 문항의 의도 모호성 — 검색 결과에 맞춰 정답을 바꾸지 않고, 별도로 검토 필요.
3. `tests/data/rag_holdout_20260910.json`(30문항)은 에이전트가 만든 스트레스 테스트라 공식 검증셋이 아닙니다 — 데이터팀 검토 후 정식 채택 여부 판단 필요.
