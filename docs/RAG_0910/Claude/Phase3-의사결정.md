작성일: 2026-09-10

## 결정할 것

**hit@1 목표(75%) 달성을 위해 검색 임베딩을 Gemini API로 전환할지 여부.**

Phase 2 실험 결과, 로컬 무료 모델(all-MiniLM-L6-v2)로는 예문을 추가해도 최대 72.31%까지만 올라가고, **Gemini `gemini-embedding-001`로 모델을 바꾸는 것만이 75% 목표를 실제로 넘긴 유일한 방법**이었습니다(76.92%).

이건 이전에 이미 한 번 내린 결정(`docs/RAG_0909/embedding-chromadb-의존성.md`)을 뒤집는 것이라 다시 명시적으로 확인이 필요합니다. 그때는 8규칙 샘플 기준 3개 모델이 전부 동률(hit@3 75%)이라 API 비용이 없는 로컬 모델을 택했지만, 지금은 38규칙 실데이터 기준 **Gemini가 로컬보다 hit@1 +6%p 명확히 앞섭니다.**

## 옵션

| 옵션 | hit@1 | 장점 | 단점 |
|---|---|---|---|
| **A. 현행 유지** | 70.77% | 무료, API 의존성 없음, 지연시간 낮음 | 목표(75%) 미달 |
| **B. 로컬 + 예문5개 enrich** | 72.31% | 무료, 구현 간단(`indexing.py`에 예문 병합 로직 추가) | 목표(75%) 여전히 미달, R-01류 근본 문제 그대로 |
| **C. Gemini API 전환** | 76.92% | 목표 달성, hit@3도 89.23%로 개선 | API 비용 발생, free tier rate limit(테스트 중 실제로 걸림 — 학생 다수 동시 사용 시 문제될 수 있음), 쿼리마다 외부 호출로 지연시간 증가, Gemini 장애 시 검색 자체가 막힘(현재는 `IndexUnavailableError`로 폴백하지만 실패 빈도가 늘어남) |
| **D. B+C 결합** | 미실험 | 잠재적으로 더 높을 가능성 | 추가 실험 필요, 결정 전 확인 필요 |

## 공통으로 남는 문제 (모델과 무관)

- **R-01(형용사+be동사)**: `He tired after school.`, `He hungry now.` — 로컬·Gemini 둘 다 검색 실패. 규칙 예문 자체를 데이터팀과 함께 보강해야 할 가능성.
- **R-08 ⟷ R-05/R-12 계열 혼동**: `These book are new.`, `These apple are fresh.` — 규칙 개념이 실제로 겹쳐서 임베딩이 구분 못 함. 데이터팀과 규칙 체계 재검토 필요.

이 두 가지는 어떤 옵션을 선택하든 별도로 처리해야 합니다.
