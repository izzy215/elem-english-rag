## 2-1. Top-K 1/3/5 비교

k=5로 실제 검색을 다시 돌려 측정.

| k | hit율 |
|---|---|
| 1 | 70.77% (hit@1, k와 무관 — 항상 1위만 봄) |
| 3 | 87.69% |
| 5 | 89.23% (+1.5%p, 65건 중 1건만 추가 회복) |

**결론: Top-K 확대는 hit@1 개선에 구조적으로 기여할 수 없음**(hit@1은 정의상 1위만 보므로 k와 무관). hit@3→5도 미미한 개선(1건)뿐이고, top-3에도 없던 8건 중 7건은 k=5로도 여전히 못 찾음 — 이 경로는 **목표 달성 수단에서 제외**.

## 2-2. 예시문(오답 문장) 포함 임베딩 — 로컬 모델(all-MiniLM-L6-v2)

`errors.jsonl`(400건, eval 문장과 중복 0건 확인)에서 규칙별 오답 예문을 규칙 텍스트에 덧붙여 재임베딩. 임시 인메모리 컬렉션으로 실험(운영 색인 미변경).

| 규칙당 추가 예문 수 | hit@1 | hit@3 |
|---|---|---|
| 0개(기준선) | 70.77% | 87.69% |
| 3개 | 70.77% | 86.15% (오히려 하락) |
| **5개** | **72.31%** | 87.69% |
| 10개(전체) | 67.69% (하락) | 83.08% (하락) |

**결론: 예문을 너무 많이 넣으면 규칙 임베딩끼리 서로 비슷해져서 오히려 변별력이 떨어짐** — 5개 근처가 최적점으로 보이나, 그래도 +1.5%p 수준(72.31%)으로 **목표(75%)에는 못 미침**. R-01 미스 2건은 예문을 추가해도 그대로 재현됨(예문 자체가 도움이 안 되는 근본적으로 다른 문제로 보임).

## 2-3. 임베딩 모델 재테스트 — Gemini `gemini-embedding-001`

실데이터 38규칙 전체로 재테스트(요금제 free tier rate limit로 청크 분할 실행).

| 모델 | hit@1 | hit@3 |
|---|---|---|
| all-MiniLM-L6-v2(로컬/무료) | 70.77% | 87.69% |
| **gemini-embedding-001**(API) | **76.92%** | **89.23%** |

**목표(hit@1 ≥ 75%)를 유일하게 달성.** 다만:
- Pattern①(R-01이 자기 오류유형에서 검색 안 됨: `He tired after school.`, `He hungry now.`)은 **모델을 바꿔도 그대로 재현** — 임베딩 모델 문제가 아니라 R-01 규칙 텍스트/예문 자체의 표현 범위 문제로 보임 (데이터팀 검토 필요 후보)
- Pattern②(R-08⟷R-05/R-12 계열 혼동)도 모델 무관하게 지속 — 규칙 개념 중복 이슈로 보임(검색 튜닝 대상 아님)
- **운영 반영 시 트레이드오프**: 쿼리 임베딩마다 Gemini API 호출 필요 → (a) API 과금 발생 (b) free tier 100 req/min 제한에 테스트 중 실제로 걸림(재시도 로직 필요) (c) 로컬 대비 지연시간 증가, 외부 서비스 장애가 검색 장애로 전이

다국어 로컬 모델(paraphrase-multilingual-MiniLM-L12-v2)은 이 환경의 `sentence-transformers` 패키지가 DLL 로드 오류로 깨져 있어 이번엔 재테스트 못 함(환경 문제, 별도 해결 필요).
