# 초등 영어학습 · RAG 맞춤 복습 — 간단 기획서 (v0.1)

작성일: 2026-09-04 · 작성: 팀장 · 상태: **초안 (팀 회의용)**
PRD는 이 문서로 범위를 합의한 뒤 작성한다.

---

## 1. 한 줄 정의

> 초등학생이 Level·Unit을 골라 단어·문장을 학습하고, AI가 낸 문제를 풀면 **틀린 내용을 기록해 두었다가 RAG가 교재에서 근거를 찾아 그 학생에게 맞는 문제와 설명을 다시 만들어 주는** 학습 서비스.

핵심 루프: **학습 → 오답 기록 → RAG 교재 검색 → 맞춤 문제·오답 설명 → 다시 학습**

## 2. 왜 만드는가

- 수업(NIPA-Google Study Jam PBL) 요건: Gemini API · RAG · 프롬프트 엔지니어링 · (선택) BigQuery/Vertex AI
- 팀 목표: **RAG를 중심**에 두고, "검색 정확도를 숫자로 개선했다"를 발표의 핵심으로 삼는다
- 차별점: 문제은행이 아니라 **교재 근거 + 학생 오답 이력**으로 문제가 학생마다 달라진다

## 3. 대상 사용자

| 사용자 | 설명 | 1차 |
|---|---|---|
| 학생 | 초등 3~6학년 (Level로 구분) | ○ |
| 교사/관리자 | 골든 데이터 검수, 정확도 확인 | △ (화면 최소) |

로그인은 만들지 않는다. 학생은 **이름 드롭다운**으로 선택 (데모용 학생 A / 학생 B).

## 4. 1차 범위

| 기능 | 1차 | 비고 |
|---|---|---|
| Level 선택 | ○ | 교재 학년 기준 1·2·3 |
| Unit 선택 | ○ | 교재 목차 그대로 |
| 단어 학습 | ○ | 골든 데이터의 단어·뜻·예문 표시 |
| 문장 학습 | ○ | 골든 데이터의 문장·뜻 표시 |
| AI 문제 생성 | ○ | Unit 단어 + RAG 조각 + **학생 최근 오답** → 객관식/빈칸 |
| RAG 검색 (학습용) | ○ | **핵심.** 학생 오답·Unit 단어로 04_rag_chunks 검색 → 문제 생성·오답 설명의 근거. 평가셋으로 정확도 측정 |
| RAG 검수 경고 (등록용) | ○ | 같은 인덱스로 선생님이 등록한 문장을 검색해 "교육과정 범위 밖 단어 / 기존 문장과 중복" 경고 한 줄. 등록 폼에 표시, 별도 화면 없음 |
| 오답 설명 | ○ | 초등 눈높이 설명 + 교재 출처 표시 |
| 듣기 (TTS) | ○ | 단어·문장 카드에 듣기 버튼. sample의 캐시 TTS 그대로 이식 |
| 말하기 평가 | ○ | 녹음 → STT(Gemini 음성 입력) → 원문과 유사도로 점수. **음소 단위 발음 평가는 하지 않음** |
| 로그인 / 회원가입 | ✕ | 이름 드롭다운으로 대체 |
| 개인별 복습 화면 | ✕ | 별도 화면 없이 **문제 생성 프롬프트에 오답 반영**으로 흡수 |
| 스토리 생성 · XP · 배지 · 랭킹 | ✕ | 2차 로드맵 슬라이드에만 |

## 5. 화면 목록 (5개)

1. **시작**: 학생 이름 선택 → Level 선택
2. **Unit 목록**: 해당 Level의 Unit 카드
3. **학습**: 단어 카드(뜻·예문·듣기) → 문장 카드(듣기·따라 말하기 → 점수)
4. **문제 풀기**: AI 문제 3~5개, 즉시 채점
5. **오답 설명**: 틀린 문제별 설명 + "교재 N쪽" 근거, [다시 풀기] 버튼
6. (관리자, △) **정확도 대시보드**: 평가셋 기준 검색 정확도, 개선 전후 비교. 소스 등록 폼에는 RAG 검수 경고 한 줄만 추가

> RAG의 주인공은 **학습용**(학생 화면·데모·정확도 숫자). 검수용은 같은 엔진의 부가 입구로, 등록 시 경고 한 줄 이상 확장하지 않는다. (2026-09-04 결정)
> 2026-09-04 변경: RAG 검수 경고 · 듣기(TTS) · 말하기 평가를 △/2차에서 **1차(○)로 승격**. 말하기 평가는 유사도 채점까지만.

## 6. 시스템 구성

```
브라우저 (HTML + JS, 목업 스타일 유지)
   │  /api/...
FastAPI (server.py)
   ├─ A. RAG 엔진 (인덱스 하나, 입구 둘)   임베딩 + Chroma (data/chroma/)
   │     ├─ 학습용 ○  /api/rag/search     학생 오답·단어 → 교재 조각 (B·C의 근거)
   │     └─ 검수용 ○  /api/rag/check      선생님 등록 문장 → 범위 밖 단어·중복 경고
   ├─ B. 문제 생성     /api/quiz           Gemini + RAG 조각 + 오답 로그
   ├─ C. 오답 설명     /api/explain        Gemini + RAG 조각 → 출처 표시
   ├─ D. TTS ○        /api/tts/{id}       Gemini TTS, 파일 캐시 (sample에서 이식)
   └─ E. 말하기 평가 ○  /api/speak          녹음 업로드 → Gemini STT → 원문 유사도 점수
데이터
   ├─ 골든 데이터셋 (외부 팀 제공)  → 단어·문장·chunks·평가셋
   ├─ 학생 DB (JSON → 여유 시 BigQuery) → 진도 · quiz_log · wrong_words
   └─ RAG 저장소 (Chroma, data/chroma/) ← chunks.jsonl 임베딩, Git 제외
설정: .env (Gemini 키·모델) → config.py
```

이미 있는 것: FastAPI 뼈대, `.env`/config, TTS 캐시, 이벤트 로그, 승인 워크플로우(검수 화면에 재활용 가능)

## 7. 데이터 — 골든 데이터셋

**담당: 골든 데이터셋 팀 · 상세 기획서 별도 작성 예정.**
이 문서에서는 우리 서비스가 **받을 형식(인터페이스)**만 정한다. 형식은 데이터팀과 협의 후 확정.

| 파일 (안) | 내용 | 서비스에서 쓰는 곳 |
|---|---|---|
| `words.csv` | level, unit, word, meaning, example, source_page | 단어 학습, 문제 생성 |
| `sentences.csv` | level, unit, sentence, meaning, source_page | 문장 학습, 문제 생성 |
| `chunks.jsonl` | id, text, level, unit, source_page | **RAG 검색 대상 (04_rag_chunks)** |
| `eval.csv` | question, expected_chunk_id 또는 expected_answer | **검색 정확도 측정 (05_evaluation)** |

데이터팀에 요청할 사항 (작성 예정):
- [ ] 원본 교재 후보와 저작권 확인 (교육부 기본 어휘 목록 등)
- [ ] Level·Unit 정의 (몇 학년 = Level 몇, Unit당 단어 수)
- [ ] 1차 납품 범위: 데모용 Unit 2~3개, 단어 50~100개면 충분
- [ ] 평가셋 최소 30문항
- [ ] 납품 일정: **1주차 말** (RAG 개발이 2주차에 시작되므로)

데이터가 늦어질 경우 대비: 개발팀이 임시 샘플 데이터(단어 20개)로 먼저 개발하고 나중에 교체한다.

확인 필요: 각 소스의 정확한 이용 조건은 데이터팀이 납품 전에 한 번 더 확인. (2026-09-04 추가)

## 10. 성공 기준

- **데모 60초**: Level → Unit → 단어 학습 → 문제 3개 → 1개 틀림 → 근거 있는 설명 → 다시 풀기에서 틀린 단어 우선 출제 (학생 B와 다름)
- **숫자**: 평가셋 30문항 기준 검색 정확도(상위 3개 안에 정답 포함) **80% 이상**, 개선 전후 비교 그래프 1장
- **비용**: 무료 티어 내 운영 (TTS 캐시, 임베딩 1회 생성)
