# 데이터 제작 계획 — 참고자료에서 우리 데이터셋까지 (v0.1)

작성 2026-09-06 · 팀장 · 대상: 데이터팀 + 개발팀
**한 줄**: 참고자료(NCIC 어휘 목록 등)는 **재료**다. 우리가 쓸 데이터는 **직접 만든다**. 이 문서는 그 만드는 과정이다.

> 오해 방지: 7.1의 소스 목록은 "가져다 쓰면 되는 데이터"가 아니라 "단어를 고를 때 참고하는 목록"이다. 뜻 · 예문 · 설명 조각 · 오류 문장 · 평가셋은 **전부 우리가 써야 한다.**

---

## 0. 완성품이 뭔가 (이게 나와야 끝)

| 파일 | 한 줄 = | 1차 목표량 | 쓰는 곳 |
|---|---|---|---|
| `units.csv` | Unit 하나 (level, unit, title) | 3 Unit | Unit 목록 |
| `words.csv` | 단어 하나 (뜻 · 예문 · Unit) | **60단어** (Unit당 20) | 단어 카드 · 문제 |
| `sentences.csv` | 문장 하나 (뜻 · Unit) | **30문장** (Unit당 10) | 문장 카드 · 문장 고치기 |
| `grammar.jsonl` | 오류 문장 하나 (오류 · 정답 · 유형 · 근거) | **60개** (유형 6 × 10) | 문장 고치기 문제 |
| `chunks.jsonl` | 설명 조각 하나 (RAG 검색 대상) | **~120개** (단어 60 + 규칙 6 + 문장 30 + …) | 오답 설명 근거 |
| `eval.csv` | 평가 질문 하나 (질문 · 정답 조각 id) | **30문항** | RAG 정확도 |

지금 있는 것: 개발팀 임시 샘플 20단어 · 데이터팀 문법 오류 100개(→ grammar.jsonl의 원형). **나머지는 0.**

## 1. 제작 파이프라인 (6단계)

```
참고자료 ─▶ ① 범위 정하기 ─▶ ② 단어·문장 쓰기 ─▶ ③ 설명 조각 쓰기 ─▶ ④ 오류 문장 쓰기 ─▶ ⑤ 검수 ─▶ ⑥ 평가셋
 (재료)      Unit·단어 선정     words · sentences     chunks            grammar          02_golden    eval
```

### ① 범위 정하기 — 데이터팀 + 팀장 · 1일
- **입력**: NCIC 초등 권장 어휘 800 (참고), Cambridge YLE 주제 분류 (참고), 데이터팀 샘플의 오류 유형 10개
- **할 일**: Level 2 하나로 고정. Unit 3개 주제 정하기 (예: Animals · Food · School). Unit당 단어 20개를 **800 목록 안에서 고른다** (없으면 넣지 않는다 — 이게 "범위 기준")
- **출력**: `units.csv` 3줄 + 단어 60개 목록 (뜻 없음)
- **끝 기준**: 단어 60개가 표에 있고, 모두 초등 범위라고 데이터팀이 확인함

### ② 단어·문장 쓰기 — 데이터팀 · 2일
- **입력**: ① 단어 목록
- **할 일**: 단어마다 뜻 1개 · 예문 1개. Unit마다 문장 10개(단어가 쓰인 짧은 문장) · 뜻
- **방법**: Gemini에게 초안 생성 → **사람이 한 줄씩 검수** (초등 수준인가, 예문에 그 단어가 있나, 뜻이 하나로 명확한가)
- **출력**: `words.csv` 60줄, `sentences.csv` 30줄
- **끝 기준**: 빈 칸 없음 · id 중복 없음 · 예문에 단어 포함 100%

### ③ 설명 조각 쓰기 — 데이터팀 · 2일 (RAG의 핵심 재료)
- **입력**: ② 결과
- **할 일**: RAG가 검색해서 AI에게 줄 **설명 문장**을 조각 단위로 쓴다.
  - 단어 조각 (60): `"rabbit은 '토끼'예요. 예문: The rabbit can jump. (Unit 3 Animals)"`
  - 규칙 조각 (6~10): 오류 유형별 설명. 데이터팀 샘플의 `retrieved_context`가 바로 이것 → **유형별로 1개씩 대표 조각으로 정리**
  - 문장 조각 (30, 선택): 문장 + 뜻 + 쓰임
- **방법**: 단어 조각은 ②에서 규칙으로 자동 조립 (RAG 담당 스크립트). 규칙 조각은 사람이 씀
- **출력**: `chunks.jsonl` ~100줄, 각 줄에 `id · text · level · unit · kind(word|rule|sentence) · ref_id`
- **끝 기준**: 모든 단어에 조각 1개 · 모든 오류 유형에 규칙 조각 1개

### ④ 오류 문장 쓰기 — 데이터팀 · 1일
- **입력**: ② 문장 30개, 오류 유형 6개 (10개 중 초등에 맞는 것으로 축소)
- **할 일**: 문장마다 오류 유형 1~2개를 적용한 **틀린 버전** 만들기. 정답 = 원문. 근거 = ③의 규칙 조각 id
- **방법**: 데이터팀 샘플 100개 중 Level 2 단어로 된 것 재활용 + Gemini 초안 + 검수
- **출력**: `grammar.jsonl` 60줄 (`id · unit · error_type · error · correct · rule_chunk_id · feedback`)
- **끝 기준**: 오류 문장이 실제로 틀렸고, 고치면 정답과 일치

### ⑤ 검수 (02_golden) — 데이터팀 전원 · 1일
- **체크리스트**: 초등 3~6학년이 아는 단어만 / 뜻 1개 / 예문에 단어 포함 / id 중복 없음 / 오류 문장이 정말 틀림 / 규칙 설명이 초등 눈높이
- **방법**: 두 사람이 교차 검수. 애매하면 뺀다 (양보다 정확)
- **출력**: `data/golden/` 에 최종 파일 6개 납품
- **끝 기준**: 관리자 화면 "골든 데이터" 패널에 파일이 뜨고 개수가 맞음

### ⑥ 평가셋 (05_evaluation) — 데이터팀 + RAG 담당 · 1일
- **할 일**: "학생이 물어볼 법한 질문" 30개 + 정답 조각 id. 유형 섞기: 뜻→단어 10 · 단어→뜻 10 · 문법 5 · 주제 5. **조각 문장을 그대로 베끼지 않는다**
- **출력**: `eval.csv` 30줄
- **끝 기준**: RAG 담당이 스크립트로 돌려 hit@3 숫자가 나옴

## 2. 일정 (데이터팀 기준 · 총 8일)

| 일차 | 단계 | 산출물 |
|---|---|---|
| 1 | ① 범위 | units.csv · 단어 60 목록 |
| 2~3 | ② 단어·문장 | words.csv · sentences.csv |
| 4~5 | ③ 조각 | chunks.jsonl |
| 6 | ④ 오류 문장 | grammar.jsonl |
| 7 | ⑤ 검수 | data/golden/ 납품 → **개발팀 교체** |
| 8 | ⑥ 평가셋 | eval.csv → RAG 실험 시작 |

개발팀은 그동안 임시 샘플로 개발. 7일차 납품 시 파일만 교체.

## 3. 역할

| 누가 | 하는 일 |
|---|---|
| 데이터팀 | ①~⑥ 작성 · 검수 (본체) |
| 팀장 | ① 같이 결정, 진행 확인, 막히면 Gemini 프롬프트 제공 |
| RAG 담당 | ③ 단어 조각 자동 조립 스크립트, ⑥ 채점 스크립트, 파일 형식 검증 |
| TTS 담당 | 납품 후 단어·문장 60+30개 음원 사전 생성 |

## 4. 참고자료의 진짜 용도

| 자료 | 용도 | 안 하는 것 |
|---|---|---|
| NCIC 초등 권장 어휘 800 | ①에서 단어 고를 때 **범위 체크** · 관리자 검수 경고 기준 | 여기서 데이터를 가져오지 않음 (단어만 있고 뜻·예문 없음) |
| Cambridge YLE 주제표 | ①에서 Unit 주제 고를 때 참고 | |
| 교과서 | Unit 주제 참고 | 본문 사용 안 함 |
| 데이터팀 샘플 100개 | ③ 규칙 조각, ④ 오류 문장의 **출발점** | 그대로 쓰지 않고 Level 2 단어에 맞춰 다시 씀 |
