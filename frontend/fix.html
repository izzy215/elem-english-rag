이 화면에서 데이터가 쓰이는 곳

student_error"학생이 쓴 문장"으로 화면에 표시 → 문제
error_type위 칩(필터)과 문장 아래 태그
correct_expression학생이 고쳐 쓴 문장과 비교해 채점 (대소문자·구두점 무시)
retrieved_context벡터DB(Chroma)에 들어갈 조각. 실제 서비스에선 학생 문장으로 검색해서 이걸 찾아옴
feedbackLLM이 근거를 보고 만들 문장의 예시. 실제 서비스에선 매번 생성
실제 서비스에서는
  1. 학생이 문장을 씀 (또는 문제로 제시)
  2. 서버가 그 문장으로 retrieved_context 100개 중 가장 비슷한 것을 검색 (RAG)
  3. 찾아온 근거 + 학생 문장 + 정답을 Gemini에 주고 feedback 같은 문장을 생성
  4. 틀린 문장은 오답노트에 쌓여 다음에 먼저 나옴

지금 데모는 2·3번을 파일에서 바로 꺼내 보여주는 것. 검색·생성은 RAG 담당·팀장 구현 후 실제 동작.
